# Spec Delta

## Purpose

定义用户与收藏条目的稳定 MD5 标识规则，使主键可由业务数据推导并在数据库、API 与客户端之间保持一致的字符串格式。

## ADDED Requirements

### Requirement: 用户标识使用用户名派生 MD5

系统 MUST 使用用户名派生用户主键，取值为 `MD5(username)` 计算出的 32 位小写十六进制字符串；注册时写入该标识，登录签发的 JWT `sub` 与既有用户记录 MUST 使用同一格式。

#### Scenario: 注册新用户

- **WHEN** 用户以用户名 `alice` 完成注册
- **THEN** 新用户记录的 `id` 为 `MD5("alice")` 对应的 32 位小写十六进制字符串

#### Scenario: 登录返回用户标识

- **WHEN** 已注册用户成功登录
- **THEN** 登录响应中的用户 `id` 与 JWT `sub` 均为该用户的 32 位 MD5 字符串

#### Scenario: 用户名唯一性冲突

- **WHEN** 注册时提交的用户名已存在
- **THEN** 系统继续返回用户名已存在错误，不创建第二个用户

### Requirement: 收藏条目标识使用作用域化 MD5

系统 MUST 使用 `MD5(userId + ":" + space + ":" + normalizedUrl)` 计算收藏条目标识，结果为 32 位小写十六进制字符串；同一用户在同一空间收藏同一规范化链接时 MUST 得到相同标识。

#### Scenario: 同一空间重复收藏同一链接

- **WHEN** 同一用户在同一空间再次收藏已存在的规范化链接
- **THEN** 系统返回既有重复收藏提示，不创建具有不同标识的重复条目

#### Scenario: 不同用户收藏同一链接

- **WHEN** 两个不同用户收藏同一规范化链接
- **THEN** 两条收藏记录拥有不同标识，且均可独立保存

#### Scenario: 同一用户在不同空间收藏同一链接

- **WHEN** 同一用户分别在 `star` 和 `kitchen` 空间收藏同一规范化链接
- **THEN** 两条收藏记录拥有不同标识，并分别归属对应空间

### Requirement: 标识格式与校验

系统 MUST 将用户与收藏条目标识作为 32 位小写十六进制字符串对外返回；收藏条目接口收到不符合该格式的路径标识时 MUST 返回 `INVALID_INPUT`，不得按数字主键解析。

#### Scenario: 查询合法收藏标识

- **WHEN** 客户端使用 32 位小写十六进制标识请求收藏详情
- **THEN** 系统按该标识和当前用户、空间范围查询并返回对应收藏

#### Scenario: 查询非法收藏标识

- **WHEN** 客户端使用 `1234` 或其他非 32 位十六进制字符串请求收藏详情
- **THEN** 系统返回 `INVALID_INPUT` 且不执行收藏查询

### Requirement: 既有主键迁移保持关联完整

数据库迁移 MUST 将既有用户、收藏条目及其关联记录的整数主键转换为 MD5 标识，并保持目录归属、标签关联和传输内容归属不变；发现同一用户同一空间存在重复规范化 URL 时 MUST 在写入前终止迁移并报告冲突。

#### Scenario: 迁移既有收藏数据

- **WHEN** 数据库包含既有用户、目录、收藏、标签和传输内容
- **THEN** 迁移完成后所有用户与收藏条目使用 MD5 标识，关联表指向对应新标识且记录数量不变

#### Scenario: 迁移发现重复链接

- **WHEN** 同一用户同一空间存在两条规范化 URL 相同的收藏条目
- **THEN** 迁移终止并报告冲突，不删除、不合并且不覆盖任何收藏记录
