# Spec Delta

## Purpose

为收藏夹用户提供一个安全的目录级 AI 对话能力，使用户在当前空间和目录中打开悬浮聊天入口，基于该目录的收藏上下文向 AI 提问并继续讨论。该能力不向浏览器暴露第三方 AI 凭据，也不默认将外部网页全文发送给模型。

## ADDED Requirements

### Requirement: 当前收藏页面提供 AI Chat 入口

收藏夹页面 SHALL 在用户已登录时显示悬浮 AI Chat 按钮；按钮在桌面和 Pad/窄屏布局中均可操作，并不得遮挡目录树、搜索栏或收藏条目的主要操作。

#### Scenario: 打开当前目录聊天

- **WHEN** 用户进入某个收藏目录并点击悬浮 AI Chat 按钮
- **THEN** 系统打开聊天面板，并将当前空间、目录名称和目录路径显示为当前会话上下文

#### Scenario: 页面切换后上下文更新

- **WHEN** 用户在聊天面板关闭后切换到另一个空间或目录并再次打开聊天
- **THEN** 新会话使用新的空间和目录上下文，不继续误用上一个目录的上下文

### Requirement: AI 对话接口必须使用当前用户和目录上下文

系统 SHALL 提供认证的 AI 对话能力，服务端依据当前用户身份校验请求，并只接受由客户端明确提交的当前空间、目录标识、目录路径、收藏摘要和对话消息；服务端不得依据客户端提交的用户标识授权访问其他用户数据。

#### Scenario: 发送目录问题

- **WHEN** 已登录用户提交一个非空问题和当前目录上下文
- **THEN** 系统向 AI 服务发送受限的目录上下文与对话消息，并返回 AI 回复文本

#### Scenario: 未登录请求被拒绝

- **WHEN** 请求缺少有效 Bearer JWT 或 JWT 无法通过当前认证中间件
- **THEN** 系统返回 HTTP 401，且不调用外部 AI 服务

#### Scenario: 空问题被拒绝

- **WHEN** 用户提交空白消息或超过接口规定长度的消息
- **THEN** 系统返回 HTTP 400，说明输入无效，且不调用外部 AI 服务

### Requirement: 目录上下文必须受限并保护敏感信息

发送给 AI 服务的目录上下文 SHALL 只包含当前用户可见收藏的必要元数据，并限制收藏条目数量、单条字段长度和总上下文大小；系统 MUST 不发送密码、JWT、第三方 API Key、请求头、文件二进制和未明确授权的网页全文。

#### Scenario: 超出上下文容量

- **WHEN** 当前目录收藏数量或文本总量超过上下文上限
- **THEN** 系统截断或分页摘要上下文并明确告知 AI 当前上下文已受限，不因上下文过大导致请求无限增长

#### Scenario: 日志脱敏

- **WHEN** AI 请求成功或失败并产生应用日志
- **THEN** 日志可记录请求 ID、用户标识摘要、当前空间、目录标识、耗时和错误类别，但不得记录 API Key、JWT、完整对话正文或完整收藏正文

### Requirement: AI 供应商错误和超时可理解地返回

当外部 AI 服务不可用、超时、配置缺失或返回无法解析的响应时，服务端 SHALL 记录脱敏错误并返回稳定的错误结构；客户端 SHALL 保留用户刚输入的问题并显示可理解的失败提示。

服务端 SHALL 将外部供应商的认证失败、模型/路径不存在和限流分别映射为稳定错误码，并只记录供应商 HTTP 状态码，不得记录供应商响应正文或凭据。

#### Scenario: 外部服务超时

- **WHEN** AI 服务在服务端规定超时时间内未完成响应
- **THEN** 服务端终止该调用并返回可识别的 AI_TIMEOUT 错误，客户端保留问题内容并允许重试

#### Scenario: AI 配置缺失

- **WHEN** 服务端未配置 API Key、Base URL 或模型名称
- **THEN** AI 接口返回服务不可用错误，不将配置值或凭据写入响应或日志

#### Scenario: 供应商认证失败

- **WHEN** Agnes 返回 HTTP 401 或 403
- **THEN** 服务端返回 `AI_AUTH_FAILED`，并在脱敏日志中记录供应商状态码

#### Scenario: 模型或路径不存在

- **WHEN** Agnes 返回 HTTP 404
- **THEN** 服务端返回 `AI_MODEL_NOT_FOUND`，并在脱敏日志中记录供应商状态码

#### Scenario: 供应商限流或额度不足

- **WHEN** Agnes 返回 HTTP 429
- **THEN** 服务端返回 `AI_RATE_LIMITED`，并在脱敏日志中记录供应商状态码

### Requirement: 聊天面板支持连续讨论

聊天面板 SHALL 按顺序显示用户消息和 AI 回复，支持在同一会话中继续发送问题；发送期间 SHALL 显示进行中状态并阻止重复提交，失败时 SHALL 允许重新发送。

#### Scenario: 连续追问

- **WHEN** 用户收到第一次 AI 回复后提交第二个问题
- **THEN** 系统将会话中必要的历史消息连同当前目录上下文发送，并按顺序追加第二个 AI 回复

#### Scenario: 发送失败后重试

- **WHEN** 一次 AI 请求失败
- **THEN** 失败消息可见、原问题仍可恢复或重新发送，且聊天面板不被关闭
