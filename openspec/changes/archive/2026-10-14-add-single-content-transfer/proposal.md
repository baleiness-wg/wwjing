# Proposal

## Why

当前登录后的前端路由仍停留在工具占位页，用户无法从首页进入清晰的工具空间，也无法在同一账号的不同设备之间传递内容。本次变更建立最小可用的信息架构，并增加一个只属于当前账号的单条内容存储能力，满足文件和文字在设备间同步取用的需求。

## What Changes

- 登录成功后进入首页 `/`，首页只显示 `Hello`，不提前展示业务统计或空状态模块。
- 增加顶部一级导航 `首页`、`工具` 和用户入口。
- 工具空间提供“数据传输”入口及 `/tools/transfer` 页面。
- 数据传输支持保存一种当前内容：文件或文字；同一账号始终只保留一条内容。
- 同一账号再次保存文件或文字时直接覆盖已有内容，文件和文字可以互相覆盖。
- 允许同一账号在其他设备登录后查看文字、复制文字或下载文件；不同账号不得访问该内容。
- 文件单个大小限制为 100 MB，前端和后端均执行校验。
- 增加保存、读取元数据/文字和下载文件所需的认证 API 与 PostgreSQL 持久化结构。

## Capabilities

### New Capabilities

- `single-content-transfer`: 为已登录账号提供单条、可覆盖的文件或文字内容存储，以及同账号跨设备读取和下载能力。

### Modified Capabilities

无。

## Impact

- 前端：Vue Router、应用布局、首页、工具目录、数据传输页面及请求封装。
- 后端：Node/Express 认证路由组、内容上传/读取/下载接口、请求大小限制和错误响应；Go 服务不承载本功能。
- 数据库：PostgreSQL 新增按 `user_id` 唯一约束的内容表，使用单个二进制 payload 字段同时存储 UTF-8 文字和文件内容。
- 部署与接口文档：需要更新数据库迁移、构建版本信息及相关 HTTP 接口说明。
