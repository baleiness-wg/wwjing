# Design

## Context

当前 Web 端使用 Vue 组件、Vue Router 和 Element Plus，路由已将首页、工具页和数据传输页区分开，认证拦截位于路由层。导航布局主要由 `source/web/src/layouts/AppLayout.vue` 及其样式承担；本变更不需要后端接口或路由协议调整。具体行为契约见 `specs/navigation-layout/spec.md`。

## Goals / Non-Goals

**Goals:**

- 在现有应用布局中建立明确的左侧菜单状态模型，包括整体菜单展开/收起和工具组展开/收起。
- 以当前路由驱动导航激活态，使首页、工具组和工具子项在直接访问及页面跳转后保持一致。
- 复用顶部导航的墨绿色设计令牌或 CSS 变量，覆盖左侧选中项的文字、图标和必要的背景/边框强调。
- 使用项目已有图标能力或 Element Plus 图标，避免为单个按钮引入新的第三方依赖。
- 适配 Pad 浏览器的触控点击区域、键盘焦点和折叠后的图标导航状态。

**Non-Goals:**

- 不修改现有路由路径、认证守卫、后端接口或工具业务页面。
- 不新增工具业务功能，不重构整个页面内容区域。
- 不把菜单折叠状态做成跨会话持久化设置，除非现有布局已经具备该机制。

## Decisions

### 1. 在布局层集中管理导航状态

由应用布局组件维护左侧菜单的展开状态和工具组展开状态，导航项使用配置数据描述标题、图标、路由和子项。这样可以让按钮、菜单组和内容区域共享同一状态，避免在多个页面中复制导航逻辑。

备选方案是让每个页面独立渲染导航，但会导致激活态和折叠状态在路由切换时不一致，因此不采用。

### 2. 使用路由匹配决定选中态，不使用点击临时状态

选中项通过当前路由名称或路径匹配计算，工具子页面匹配时同时激活工具组。点击菜单只负责触发路由跳转或切换菜单组，不能单独写入一个可能过期的“当前选中项”变量。

备选方案是使用菜单组件的默认 active index，但直接访问、浏览器前进后退和认证跳转可能无法可靠同步，因此不作为唯一来源。

### 3. 折叠按钮放在品牌区域左侧并保持图标语义

品牌区域采用水平布局，将折叠按钮固定在鲸境标识左侧；按钮仅展示展开/收起图标，通过 `aria-label` 或等效可访问名称表达动作。菜单收起后保留窄栏图标入口，避免完全隐藏导航导致用户无法恢复展开状态。

备选方案是把按钮放在侧栏底部或使用文字按钮，前者不符合用户指定的位置，后者会继续占用品牌区域并产生语言依赖。

### 4. 统一使用墨绿色设计令牌

先查找现有顶部菜单栏使用的颜色变量或样式值，将其作为左侧激活态的唯一主色来源；如现有代码没有变量，则在布局样式作用域内提取为共享 CSS 自定义属性，再分别应用于文字、图标和轻量背景强调。

不直接继续使用 Element Plus 默认 primary 色，因为默认蓝色正是当前视觉不一致的来源。

## Risks / Trade-offs

- [Risk] 收起菜单后仅剩图标可能降低新用户对入口含义的理解 → 为每个图标提供 tooltip 或原生可访问名称，并保留清晰的图标语义。
- [Risk] 工具组展开状态与当前工具子路由不一致 → 初始化和路由变化时根据当前路径自动展开工具组；用户手动收起时仍允许暂时收起，但进入子路由时恢复可见。
- [Risk] Element Plus 默认菜单样式覆盖墨绿色激活态 → 将激活态样式放在应用布局样式的明确选择器中，并在桌面及 Pad 尺寸下检查文字、图标和背景对比度。
- [Risk] 触控区域过小导致 Pad 上误触 → 折叠按钮、工具组和子菜单项使用不小于现有设计规范的点击区域，并验证展开/收起不依赖 hover。

## Migration Plan

1. 在前端布局中替换导航渲染与样式，保持现有路由名称、路径和页面组件不变。
2. 使用已登录和未登录两类用户验证首页、工具组及数据传输页的导航状态。
3. 在桌面宽度和 Pad 浏览器宽度验证展开、收起、直接访问、浏览器后退和键盘焦点行为。
4. 若出现布局回归，回滚布局组件和其关联样式即可，不涉及数据库、接口或持久化迁移。

## Open Questions

无。图标具体外观可在实现阶段依据项目现有图标库选择，不改变规格要求。
