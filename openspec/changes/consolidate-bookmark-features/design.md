# Design

## Context

当前收藏系统由 Flutter Android/iOS 客户端、Node 服务、Web 管理端和 PostgreSQL 组成。已有代码提供平台专用跳转、分享/剪贴板入口、元数据抓取、目录管理和多空间；近期变更同时引入了 `images` JSON 数组、可空 URL 以及多个 UI 重构，需要在不破坏既有客户端数据的前提下收敛契约。

## Goals / Non-Goals

**Goals:**

- 让数据库、Node API、Flutter 模型、Web 模型对 `images` 数组和可空 URL 使用一致契约。
- 保持平台 App 定向跳转和小红书真实封面解析，并让识别结果异步写回后刷新列表。
- 让 Flutter 主页、左侧目录树和目录选择器具有明确、紧凑且可预测的交互。
- 让生产迁移可以在现有 Docker/PostgreSQL 网络和持久化数据上安全执行。

**Non-Goals:**

- 本变更不实现真实图片文件上传、对象存储或 CDN。
- 本变更不改变 kitchen/star 的空间隔离、认证协议或现有 Web 路由。
- 本变更不删除历史 `cover_url` 字段，兼容迁移完成后的旧客户端读取。

## Decisions

1. **以 `images` JSONB 数组作为新图片写入契约。**
   - 旧 `cover_url` 迁移为 `images[0]`，读取端兼容旧字段。
   - 选择 JSONB 而不是新增图片表，因为当前范围只需要有序 URL 数组，后续上传服务可以在不改变收藏主体接口的情况下扩展。

2. **URL 使用可空三元字段。**
   - `source_url`、`normalized_url`、`source_host` 均允许为空；非空 URL 复用现有规范化与重复校验，空 URL 跳过重复查询。
   - 不使用伪造 URL 或特殊占位值，避免污染搜索、跳转和重复判断。

3. **元数据识别采用客户端专用解析优先、服务端通用解析兜底。**
   - Flutter 先处理抖音和哔哩哔哩专用接口，再请求 Node 元数据服务。
   - Node 对小红书优先读取内嵌状态，随后扫描转义 CDN URL，并过滤平台 Logo。
   - 识别结果在保存完成后通过 PATCH 更新 `images`，更新完成后刷新当前列表。

4. **主页目录内容由服务端递归查询控制。**
   - Flutter 当前目录请求传 `includeDescendants=true`，主页只渲染视频卡片，不渲染子目录卡片。
   - 左侧导航和目录选择器保留目录管理职责，避免主页同时承担目录浏览和视频浏览两种信息层级。

5. **平台跳转保持原有 LinkLauncher 顺序。**
   - 不改动 Bilibili、小红书、抖音的 Deep Link 顺序；只有在所有 App 定向方式失败后才调用外部浏览器。
   - UI 卡片只负责调用统一打开回调，不在组件内自行调用 `url_launcher`。

6. **目录树状态局部化。**
   - 左侧目录导航和目录选择器各自维护折叠集合与操作高亮状态，目录选择和业务状态继续由 `AppState` 管理。
   - 这样不会把临时 UI 折叠状态写入服务端或持久化偏好。

## Risks / Trade-offs

- [Risk] 小红书页面结构持续变化导致真实封面提取失败 → 保留 Logo 过滤、测试夹具、通用 `og:image` 回退，并记录元数据失败信息。
- [Risk] 旧数据库尚未执行图片/可空 URL 迁移 → 部署前运行迁移并在 CI/CD 中执行健康检查和数据库连接检查。
- [Risk] 递归目录列表数据量增大 → 继续沿用分页、稳定排序和请求竞态 ID；后续可增加服务端深度或分页策略。
- [Risk] 异步识别完成时用户已离开表单 → 保存后的持久化只依赖条目 ID，UI 刷新前检查状态仍有效，失败只记录可见错误而不覆盖用户输入。

## Migration Plan

1. 备份 PostgreSQL 数据库。
2. 执行新增迁移，将旧封面转换到 `images` 并放宽 URL 相关字段非空约束。
3. 部署 Node 服务，确认容器与 PostgreSQL 位于同一持久化 Docker 网络。
4. 部署 Flutter/Web 客户端，验证登录、收藏列表、无 URL 新增、图片显示、平台跳转和目录递归展示。
5. 回滚时回退应用镜像；不删除 `images` 字段和数据库卷，避免旧数据丢失。
