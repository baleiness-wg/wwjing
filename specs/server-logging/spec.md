# server-logging 模块规格说明

- 版本：202610160038
- 最后更新：2026-10-16
- 模块名称：server-logging（Node 服务日志）

---

## 业务概述

server-logging 模块负责为 Node 服务提供统一的结构化日志能力，帮助开发人员和运维人员查看服务启动、HTTP 请求、业务操作和运行错误。日志在开发环境中提供便于阅读的终端输出，在生产环境中输出结构化 JSON，由 PM2、Docker、systemd/journald 或日志采集器负责保存、轮转和转发。

### 核心业务流程

- Node 服务启动时初始化统一日志模块，并输出服务名称、监听地址和运行环境。
- 每个 HTTP 请求进入 Express 后生成或复用请求编号，服务在响应头返回该编号，并在访问日志中记录请求方法、路径、状态码和响应耗时。
- HTTP 控制器使用请求级日志对象记录业务结果；不经过 HTTP 请求的数据库迁移和启动脚本使用全局日志对象。
- 请求发生异常时，错误处理中间件记录错误类型、消息、堆栈和请求编号，同时保持原有 HTTP 状态码和响应结构。
- 应用根据日志级别过滤输出，低于配置级别的日志不输出。
- 开发环境输出可读的终端日志；生产环境输出 JSON 到标准输出，不由业务应用直接绑定 Elasticsearch、Kibana 或其他日志平台。
- 日志保存周期和历史日志查询由运行平台负责；应用本身不管理日志文件、压缩和轮转。
- 日志不得记录密码、JWT、Authorization 请求头、Cookie、请求体、文件二进制和用户保存的文字正文；文件操作最多记录文件名、媒体类型和文件大小等必要元数据。

### 页面布局约束

- 本模块无独立业务页面。
- 开发环境日志应在终端以易读格式显示服务、请求和错误信息。
- 生产环境日志应以单条 JSON 记录输出，方便 PM2、Docker、systemd/journald、Filebeat 或 Fluent Bit 采集。
- 日志记录应包含可用于检索的服务名称、运行环境、时间、级别、请求编号和消息字段。

## 接口说明

本模块不新增业务 HTTP 接口，不改变现有接口路径、请求方式、请求参数和返回参数。日志通过 Node 服务标准输出提供给运行平台和日志采集器。

### 日志输出结构

- **输出方式**：标准输出 `stdout`
- **数据格式**：生产环境为 JSON，开发环境为可读终端格式
- **请求关联字段**：`req.id`
- **日志级别**：`trace`、`debug`、`info`、`warn`、`error`、`fatal`

```json
{
  "level": 30,
  "time": "2026-10-16T00:38:00.000Z",
  "service": "wwjing-server",
  "environment": "production",
  "req": {
    "id": "request-123",
    "method": "POST",
    "url": "/api/transfer/content/file"
  },
  "res": {
    "statusCode": 200
  },
  "responseTime": 42,
  "userId": "42",
  "contentType": "file",
  "fileSize": 245760,
  "msg": "file content saved"
}
```
