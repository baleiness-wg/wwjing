# 表格聊天工作台 模块规格说明

- 版本：202611230505
- 最后更新：2026-11-23
- 模块名称：chat-workbench（表格与文字聊天工作台）

## 业务概述

为已登录用户提供一个轻量表格工作台。页面以表格、文字记录和聊天面板为主要内容，聊天消息暂存于当前浏览器，不连接业务数据接口。

## 核心业务流程

- 用户点击 Header 中数据传输图标右侧唯一的聊天图标，在新标签页打开工作台。
- 用户可以编辑表格单元格内容，编辑前必须取得服务端单元格锁；其他用户实时看到编辑者姓名并不能同时进入该输入框。
- 每次编辑失焦或提交后由服务端确认保存，并通过 WebSocket 广播给所有在线用户；断线重连后通过快照恢复最新内容和编辑状态。
- 用户可以创建、进入和切换带密码的独立房间；每个房间分别保存工作表、编辑标记、锁、列宽和聊天消息，房间之间不得共享内容。
- 页面刷新后恢复当前房间内容，聊天消息不要求跨设备同步。

## 页面布局约束

- Header 仅保留一个聊天图标，位于数据传输图标右侧，点击后在新标签页打开 `/office`，不增加侧边菜单项。
- 工作台主体由表格区域和聊天区域组成，桌面端左右分栏，移动端上下排列。
- 表格提供列标题、行号、可编辑单元格、工具栏和状态栏。
- 聊天区域显示消息列表、输入框和发送按钮。
- 房间切换时必须清除前一房间的草稿、待确认更新、未读标记和编辑状态；旧房间连接的延迟消息不得更新当前房间。
- 用户初始化当前工作表时，当前内容替换为标准脱敏演示数据；初始化结果同步给房间成员，但接收方不得为每个单元格生成未读标记或编辑通知。
- 房间快照加载完成后，表格列宽根据当前表格内容自动撑开；编辑标题、列标题或单元格后同步重新计算对应列宽。
- 用户可以导入 `.xlsx` 或 `.xlsm` 文件的第一个工作表；确认后直接覆盖当前工作表，导入结果同步给房间成员，不为逐单元格生成未读标记。
- 工作表纵向滚动区域按需追加空白行，导入大量数据后可以持续向下滚动，不受当前数据行数限制。
- 导入 Excel 后标记为原生表格模式，取消工作台默认粉色标题和表头覆盖，并保留导入文件的列宽、行高及单元格样式数据。
- 新增行时先保留本地待确认值，并同时通过 WebSocket 和 HTTP 兜底保存，避免快照刷新覆盖刚输入的内容。
- 导入 Excel 后编辑单元格时，快照不得覆盖尚未提交的本地草稿；初始化工作表时恢复默认数据，同时保留并恢复已导入的 Excel 样式。
- 单元格失焦保存失败时显示明确错误；保存成功后立即显示当前编辑用户名和编辑时间，即使焦点已切换到其他单元格。

## 接口说明

- WebSocket 路径：`/api/office/ws?token=Bearer%20<token>&roomId=<roomId>&password=<password>`。
- WebSocket 消息：客户端发送 `cell:lock`、`cell:unlock`、`cell:update`、`sheet:initialize`、`sheet:replace`；服务端发送 `snapshot`、`cell:lock`、`cell:unlock`、`cell:updated`、`sheet:initialized`、`sheet:replaced`、`cell:lock:rejected` 和 `cell:update:ack`。
- `cell:lock` 和 `cell:update` 均以服务端返回的结果为准，锁与连接绑定，连接关闭后自动释放。
- HTTP 快照：`GET /api/office/snapshot`，返回 `user`、`topics` 和 `locks`。
