# 表格聊天工作台 模块规格说明

- 版本：202611272225
- 最后更新：2026-11-27
- 模块名称：chat-workbench（表格与文字聊天工作台）

## 业务概述

为已登录用户提供一个轻量表格工作台。页面以表格、文字记录和聊天面板为主要内容，聊天消息暂存于当前浏览器，不连接业务数据接口。

## 核心业务流程

- 用户点击 Header 中数据传输图标右侧唯一的聊天图标，在新标签页打开工作台。
- 用户可以编辑表格单元格内容，编辑前必须取得服务端单元格锁；其他用户实时看到编辑者姓名并不能同时进入该输入框。
- 每次编辑失焦或提交后由服务端确认保存，并通过 WebSocket 广播给所有在线用户；断线重连后通过快照恢复最新内容和编辑状态。
- 用户可以创建、进入和切换带密码的独立房间；每个房间分别保存工作表、编辑标记、锁、列宽和聊天消息，房间之间不得共享内容。
- 页面刷新后恢复当前房间内容，聊天消息不要求跨设备同步。

## 页面布局约束

- Header 仅保留一个聊天图标，位于数据传输图标右侧，点击后在新标签页打开 `/office`，不增加侧边菜单项。
- 工作台主体由表格区域和聊天区域组成，桌面端左右分栏，移动端上下排列。
- 表格提供列标题、行号、可编辑单元格、工具栏和状态栏。
- 聊天区域显示消息列表、输入框和发送按钮。
- 房间切换时必须清除前一房间的草稿、待确认更新、未读标记和编辑状态；旧房间连接的延迟消息不得更新当前房间。
- 用户初始化当前工作表时，当前内容替换为标准脱敏演示数据；初始化结果同步给房间成员，但接收方不得为每个单元格生成未读标记或编辑通知。
- 房间快照加载完成后，表格列宽根据当前表格内容自动撑开；编辑标题、列标题或单元格后同步重新计算对应列宽。
- 用户可以导入 `.xlsx` 或 `.xlsm` 文件的第一个工作表；确认后直接覆盖当前工作表，导入结果同步给房间成员，不为逐单元格生成未读标记。
- 工作表纵向滚动区域按需追加空白行，导入大量数据后可以持续向下滚动，不受当前数据行数限制。
- 导入 Excel 后标记为原生表格模式，取消工作台默认粉色标题和表头覆盖，并保留导入文件的列宽、行高及单元格样式数据。
- 新增行时先保留本地待确认值，并同时通过 WebSocket 和 HTTP 兜底保存，避免快照刷新覆盖刚输入的内容。
- 导入 Excel 后编辑单元格时，快照不得覆盖尚未提交的本地草稿；初始化工作表时恢复默认数据和工作台默认粉色标题/表头样式。
- 单元格失焦保存失败时显示明确错误；保存成功后立即显示当前编辑用户名和编辑时间，即使焦点已切换到其他单元格。
- 表格底部自动补充的空白行在首次编辑时自动物化为真实工作表行，无需先点击“＋ 行”即可保存。
- 表格渲染和服务端导入均将空或无效行归一化为空数组，避免异常数据导致页面崩溃。
- Office 页面按需加载 Excel 解析库，避免每次快照都重算列宽或重复重绘整表；实时连接正常时降低快照轮询频率，断线时继续通过快照恢复数据。
- 空白行分批增加以减少初始渲染成本，滚动接近底部时仍可继续追加并编辑。
- Office 的 HTTP 和 WebSocket 写操作分别实行服务端频率限制；超限时返回明确的限流提示，不修改或广播超限操作。
- 单元格坐标必须为非负整数，行索引不超过 9999、列索引不超过 25；异常坐标不得改变房间状态。
- 单元格中的作者 ID 按当前显示昵称区分：自己使用绿色，其他人使用雾蓝色；单元格内容保持黑色，滚动加载的行同样适用。
- 房间列表的展开和收起分别使用方向相反的箭头；加号用于新建房间。
- 输入其他房间密码时不得改变当前房间密码；验证成功后保存房间和密码，密码错误时保留目标房间以便重新输入。
- 房间密码支持中文和特殊字符，通过 HTTP 请求时使用编码后的请求头，兼容原有未编码请求。
- 本地开发代理同时转发 Office 的 HTTP 请求和 WebSocket 连接。
- 创建房间和进入房间时立即显示处理中状态，同一操作进行期间禁止重复提交；输入密码验证失败或网络错误时可再次尝试。
- 进入房间时复用密码验证返回的快照；恢复或创建房间时 HTTP 与实时连接并行，先到的快照立即显示，断线时通过 HTTP 快照兜底。
- 表格滚动追加空白行及单元格状态同步需合并高频操作，确保滚动流畅且持续编辑可用。
- 初次生成的游客 ID 持久保存在当前浏览器，刷新和切换房间不改变 ID；仅用户手动修改时更改显示 ID。
- 手动修改 ID 后，同一浏览器身份在各房间写过的单元格作者 ID 同步更新；没有身份标记的旧数据在当前房间按原 ID 兼容更新，其他用户的已标记数据不受影响。
- 页面刷新时并行恢复已保存房间和房间列表，首次渲染按需展示表格行，避免重复计算和阻塞加载。
- Office 页面首次访问时按需加载其他业务页面，避免无关页面代码拖慢工作台启动。
- 实时编辑和快照恢复针对同一单元格的同一次编辑最多通知一次；刷新或重连时历史编辑不得反复弹窗，自己的编辑不触发通知。
- 标题和表头输入采用防抖合并写入，失焦或切换房间时立即提交最后输入内容。
- 单元格失焦、点击其他单元格区域或窗口失去焦点时立即提交当前草稿；异步保存完成不得清除或覆盖后续编辑的草稿、锁或状态。
- 同一次编辑的实时更新、重复消息和快照最多提示一次，包括清空内容的编辑；自己的编辑不提示。
- Office 页面隐藏或窗口不在前台时，在通知权限已授予的情况下使用系统通知提醒其他人的新编辑；连续提醒限频，回到窗口时清除标题提醒。页面在前台时继续使用页面内提示。
- 用户关闭房间密码弹窗后，旧请求或已失效连接的延迟结果不得重新打开该弹窗。

## 接口说明

- WebSocket 路径：`/api/office/ws?token=Bearer%20<token>&roomId=<roomId>&password=<password>`。
- WebSocket 消息：客户端发送 `cell:lock`、`cell:unlock`、`cell:update`、`sheet:initialize`、`sheet:replace`；服务端发送 `snapshot`、`cell:lock`、`cell:unlock`、`cell:updated`、`sheet:initialized`、`sheet:replaced`、`cell:lock:rejected` 和 `cell:update:ack`。
- `cell:lock` 和 `cell:update` 均以服务端返回的结果为准，锁与连接绑定，连接关闭后自动释放。
- HTTP 快照：`GET /api/office/snapshot`，返回 `user`、`topics` 和 `locks`。
- HTTP 快照、单元格和锁请求使用 `X-Office-Room` 指定房间；密码写入 `X-Office-Password`，编码后使用 `X-Office-Password-Encoding: uri`，快照验证失败返回 403。
- HTTP 单元格写入可通过 `X-Office-Client-Id` 提供浏览器稳定身份；WebSocket 通过 `clientId` 参数携带同一身份，`user:rename` 包含新 ID 和原 ID，服务端同步匹配身份的作者并广播 `user:renamed`。

```json
{"type":"user:rename","oldName":"游客123456","name":"新昵称"}
```
